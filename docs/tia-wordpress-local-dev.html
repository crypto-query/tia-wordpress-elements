Local WordPress: set up and seed

TIA WordPress Elements · local development only

The local WordPress runs the live tia theme and the live WooCommerce plugins. A seed script adds test users with TIA Pro subscriptions, one user for each access case. Use this guide to set it up from nothing, or to reset it.

What runs where

Part Source In git?
tia theme Copied once from the live site Yes
WooCommerce 11.2.0, WooCommerce Subscriptions 9.3.0 bun run wp:plugins copies them from the live site No: about 80 MB of third-party code. Only the pinned versions are in git.
WordPress 7.0.7, database Docker volumes No
Test users, products, subscriptions bun run wp:seed No: the script is in git, the data is not

Before you start

You need Check
Docker Desktop docker ps works
bun bun --version
SSH access to the live server, host alias tia-investor in ~/.ssh/config ssh tia-investor true returns with no error
Run every command on the host, in the repo root. The devcontainer workspace has no Docker socket, so bun run wp:seed and the wp helper do not work there.

Set up from nothing

1. Copy the plugins from the live site

bun run wp:plugins

Expected output: woocommerce 11.2.0 and woocommerce-subscriptions 9.3.0. Do this before the first start. If you start the containers first, Docker mounts empty folders, and the theme then crashes.

2. Start the containers

Open the repo in VS Code and choose Reopen in Container. Or start only WordPress and its database from the host: 

docker compose -p tia-wordpress-elements_devcontainer -f .devcontainer/compose.yaml up -d wordpress

Keep the project name tia-wordpress-elements_devcontainer. The scripts find the container by its name, tia-wordpress-elements_devcontainer-wordpress-1. The devcontainer gives the same name when the repo folder is called tia-wordpress-elements.

3. Define the wp helper

The WordPress image has no wp-cli. This shell function runs the official wordpress:cli image with the same volumes and network. Paste it into your shell, or into ~/.zshrc: 

wp() {
    local c=tia-wordpress-elements_devcontainer-wordpress-1
    docker run --rm --user 33:33 --volumes-from "$c" --network "container:$c" \
        -e WORDPRESS_DB_HOST=database:3306 -e WORDPRESS_DB_USER=wordpress \
        -e WORDPRESS_DB_PASSWORD=wordpress -e WORDPRESS_DB_NAME=wordpress \
        wordpress:cli wp "$@"
}

4. Install WordPress at the live version

wp core install --url=http://localhost:8000 --title="TIA Local" \
    --admin_user=admin --admin_password=admin --admin_email=admin@example.com --skip-email
wp core update --version=7.0.7
wp core update-db

The live site runs WordPress 7.0.7. The Docker image can ship an older version, so update it.

5. Activate the theme and the plugins

wp theme activate tia
wp plugin activate woocommerce woocommerce-subscriptions

6. Seed the test data

bun run wp:seed

The last lines must read ok for each user, then Success: Seeded 16 users. Open http://localhost:8000/ and log in as admin / admin, or as a test user below.

What the seed makes

Test logins

Two different things. The TIA Pro role is the WordPress role tia_pro_-_annual ("TIA Pro - Annual"). A TIA Pro subscription is a WooCommerce subscription to the product TIA Pro, ID 19339, the same ID as on the live site. TIA Elite, variation 19195 of the variable product 244, counts as a TIA Pro subscription too. TIA Premium, variation 247, never counts. The role is the gate: without it there is no access. The subscription then sets the access level and the cut-off. A role with no subscription at all counts as a manual grant.

Log in at http://localhost:8000/wp-login.php with the login or the email. bun run wp:seed creates these users. The credentials work only on the local site.

The seed changes as little of the database as it can. It makes no orders, sends no email and leaves no scheduled actions, so local cron cannot change a subscription later. The seed itself changes no option except the role list, plus one option that records the roles it made. WooCommerce adds a few cache transients on the side.

Test switches

The seed also links the test mu-plugin, tests/mu-plugins/tia-elements-test.php, into wp-content/mu-plugins/. The link points to the active copy of the plugin. bun run wp:seed clean removes the link. bun run wp:use points it to the copy it activates. The mu-plugin does nothing until a request turns a switch on, with the header X-Tia-Elements-Test or the cookie tia_elements_test. Give a comma-separated list of switch names.

Switch Effect Example
wcs-unavailable Every WooCommerce Subscriptions read of a user's subscriptions throws. A Member sees the Unavailable card. curl -H 'X-Tia-Elements-Test: wcs-unavailable' http://localhost:8000/forward-returns/

Everyday tasks

Task Command
Refresh the test data (for example, when the trial dates are old) bun run wp:seed
Remove the test data only bun run wp:seed clean
Live moved to a new plugin version bun run wp:plugins stops with "live has X, pinned is Y". Change the pin in scripts/wp-plugins.sh, then run it again. After a WooCommerce change, also run wp wc update.
Run any wp-cli command wp <command> with the helper from step 3
Full reset. This command stops all containers of the project, the devcontainer too, and deletes the WordPress and database volumes. All local content is lost: 
docker compose -p tia-wordpress-elements_devcontainer -f .devcontainer/compose.yaml down -v
Then start again at step 2.

Troubleshooting

Symptom Cause Fix
HTTP 500, log shows Call to undefined function is_account_page() WooCommerce is missing or inactive. The tia theme needs it. Steps 1 and 5
Plugin folders in the container are empty The containers started before step 1 Run step 1, then docker compose -p tia-wordpress-elements_devcontainer -f .devcontainer/compose.yaml up -d --force-recreate wordpress
wp: executable file not found You ran docker exec … wp. The WordPress image has no wp-cli. Use the helper from step 3
No such container: tia-wordpress-elements_devcontainer-wordpress-1 The containers are stopped, or they run under another project name Step 2, with the project name shown there
The seed stops with "exists and is not a seed user", "is not a seed product" or "belongs to a product the seed did not make" A user, post or SKU without the seed marker uses a fixture login, one of the IDs 19339, 244, 247 and 19195, or the test SKU Remove or rename that user or post. The seed never deletes data it did not make.
The seed stops with "exists and is not the seed link" A real file sits at wp-content/mu-plugins/tia-elements-test.php Move that file away. The seed replaces only its own link.
The seed stops with "No copy of tia-wordpress-elements is active" The plugin is inactive, so the seed cannot tell which copy to link bun run wp:use, then run the seed again
A self-check line does not read ok WooCommerce Subscriptions changed a date or status rule Compare with the table above, then fix scripts/wp-seed.php
