# Theme tokens, variants and slots

The CSS layer: which variables exist, what the package ships, and how to extend it. For which of these to reach for while writing markup, see [styling.md](styling.md).

Read out of a project generated by `shadcn-svelte@1.5.0` on Tailwind v4, plus the CSS the package ships.

## The stylesheet has four imports

```css
@import 'tailwindcss';
@import "tw-animate-css";
@import "shadcn-svelte/tailwind.css";
@import "@fontsource-variable/inter";

@custom-variant dark (&:is(.dark *));
```

**`shadcn-svelte/tailwind.css` comes from `node_modules`** — that is why the CLI adds `shadcn-svelte` to `devDependencies`. It carries the `data-*` variants below, the accordion keyframes, and a `no-scrollbar` utility. Deleting the dependency to "clean up" silently removes all three.

The dark variant is generated as `&:is(.dark *)`, which matches *descendants* of `.dark` — not the `.dark` element itself.

## Tokens that exist

`--background` `--foreground`, and the same `-foreground` pairing for `--card` `--popover` `--primary` `--secondary` `--muted` `--accent`. Standalone: `--destructive` `--border` `--input` `--ring` `--radius`. Series: `--chart-1..5`, and `--sidebar` with `-foreground` `-primary` `-primary-foreground` `-accent` `-accent-foreground` `-border` `-ring`.

**`--destructive-foreground`, `--surface` and `--surface-foreground` do not exist** in the generated CSS or the package's. Utilities built on them emit nothing and fail silently. Destructive UI uses `text-destructive` over a tinted background — which is what the Button `destructive` variant does.

Each token is aliased into Tailwind through `@theme inline` as `--color-<name>`, so `--primary` powers `bg-primary`, `text-primary`, `border-primary`.

## The radius scale is multiplied

```css
--radius-sm: calc(var(--radius) * 0.6);   --radius-xl:  calc(var(--radius) * 1.4);
--radius-md: calc(var(--radius) * 0.8);   --radius-2xl: calc(var(--radius) * 1.8);
--radius-lg: var(--radius);               --radius-3xl: calc(var(--radius) * 2.2);
                                          --radius-4xl: calc(var(--radius) * 2.6);
```

Setting `--radius` rescales all seven proportionally. The React-era `calc(var(--radius) - 2px)` offsets are not what ships here.

## The eight data-* variants

The package defines these as `@custom-variant`, each matching **two** attribute forms — Bits UI's `data-state="…"` and a boolean `data-…` that is not `"false"`:

`data-open` `data-closed` `data-checked` `data-unchecked` `data-disabled` `data-active` `data-horizontal` `data-vertical`

```css
.data-open\:animate-in:where([data-state=open]),
.data-open\:animate-in:where([data-open]:not([data-open=false])) { … }
```

**`data-selected` looks like a ninth and is not** — it is commented out in the shipped CSS. `data-selected:text-red-500` still compiles, because Tailwind falls back to its own bare-attribute syntax, but it compiles to plain `[data-selected]`. That matches whenever the attribute is *present*, including `data-selected="false"` — the exact case its eight siblings exclude. For selected state, match `data-checked` or write the selector explicitly.

`data-horizontal` and `data-vertical` read `data-orientation`, so they work on any Bits UI part that exposes it.

## data-slot

247 of the 335 `.svelte` files in a full install set `data-slot="<component>-<part>"` — `button`, `card-header`, `dialog-content`, `avatar-fallback`, 260 distinct values in all. It is the intended styling and targeting hook, and components use it on each other:

```
has-data-[icon=inline-start]:pl-2      /* Button pads itself for a leading icon */
in-data-[slot=button-group]:rounded-lg /* a Button inside a ButtonGroup restyles */
```

Prefer a `data-slot` selector over editing component source or threading classes through snippets.

## The cn-* classes are inert markers

Generated components carry 29 class names prefixed `cn-` — `cn-card-action`, `cn-field-orientation-vertical`, `cn-tabs-list-variant-line`, `cn-rtl-flip`. **None of them is defined**: not in the project's CSS, not in `shadcn-svelte/tailwind.css`, not anywhere in `node_modules`. They emit nothing and are stable markers for a registry or theme to hook. Leaving them alone costs nothing; deleting them invites `update` to put them back.

## Dark mode

Class-based: `.dark` on `<html>`. `mode-watcher` handles the toggle and the FOUC-blocking script, and it is already a dependency in any project with `Sonner` installed — `sonner.svelte` imports `mode` from it to theme the toaster.

```svelte
<script lang="ts">
  import { ModeWatcher } from "mode-watcher";
  let { children } = $props();
</script>

<ModeWatcher />
{@render children?.()}
```

## Adding a custom color

Declare the raw token in both modes, then alias it into Tailwind. Both steps are required — the alias alone generates no utility.

```css
:root      { --warning: oklch(0.84 0.16 84); --warning-foreground: oklch(0.28 0.07 46); }
.dark      { --warning: oklch(0.41 0.11 46); --warning-foreground: oklch(0.99 0.02 95); }

@theme inline {
  --color-warning: var(--warning);
  --color-warning-foreground: var(--warning-foreground);
}
```

Put them in the file named by `tailwind.css` in `components.json`. A second global stylesheet is how themes end up half-applied.

Colors are OKLCH — `oklch(lightness chroma hue)`, lightness `0`–`1`, chroma `0` for grey.
